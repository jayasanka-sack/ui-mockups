Contribute · A path for every skill

What would you like to do?

The full guide, by role →
First time contributing? Set up O3 locally, pick an issue labelled for newcomers, and introduce yourself on Talk. Someone will review your first pull request. Start here → Translate? O3 ships in several languages through Transifex. Review a language you speak, or start a new one. Translate O3 → Test a release? Every release candidate goes to a QA server before it ships. Click through real workflows and report what breaks. Join release testing → Design? The O3 design system and patient-chart patterns are maintained in the open. Bring research, flows or Figma. Join the design squad → Write docs? o3-docs and the wiki always need clearer guides, updated screenshots and fixed links. Markdown and a pull request. Improve the docs → Mentor students? OpenMRS has taken part in Google Summer of Code since 2007 and runs a fellowship of two to three people a year. Both need mentors. GSoC and Fellowship →

Build · How work gets done

Squads, calls and a release every few months.

Work is organised in squads: a group of people from several organisations who meet weekly on a public call, keep a board, and ship together. Anyone can join a call. The O3 frontend deploys to the QA server every fortnight; a Reference Application release goes out several times a year, run by a release manager.
